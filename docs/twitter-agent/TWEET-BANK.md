# Darkscreen Tweet Bank

> 50+ ready-to-adapt tweet templates organized by content pillar. Replace `[bracketed text]` with real data from the platform.

## Pillar 1: UI Observations (Comparisons)

### Side-by-side comparisons

```
How [N] [category] apps design their [UI element]:

[Image grid]

[One surprising observation about the differences]
```

```
[Product A] vs [Product B]: how two of the biggest [category] approach [specific flow].

One uses [approach A]. The other uses [approach B].

[Which one works better and why, stated as observation not judgment]
```

```
We looked at [specific UI element] across [N] [category] apps.

[N] use [pattern A]
[N] use [pattern B]
[N] use [pattern C]

The outlier is [Product] — they [do something unique].
```

### Pattern surveys

```
Every way crypto [category] apps handle [specific UX challenge]:

1. [Pattern] — used by [Products]
2. [Pattern] — used by [Products]
3. [Pattern] — used by [Products]

[Which is most common and why that might be]
```

```
The [UI element] is one of the hardest things to get right in [category].

Here's how [N] products solve it — from minimal to complex:

[Screenshots arranged from simplest to most complex]
```

```
[N] approaches to [common UX problem] in crypto:

[Screenshots with labels]

Most go with [common approach]. But [Product] takes a completely different path with [alternative approach].
```

### Micro-observations

```
Small detail worth noticing: [Product] [does specific thing] in their [flow/screen].

Most [category] apps [do the standard thing instead].

[Why this matters for the user]
```

```
[Product]'s [specific screen] quietly does something that most [category] apps don't:

[Specific observation]

It's a one-line change but meaningfully changes how the flow feels.
```
